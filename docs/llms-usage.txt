# knist

> Kotlin製ニューラルネットワークライブラリ。DSLでレイヤーを積み上げてモデルを構築する。
> 型がチェーン全体で追跡され、IO型の不整合はコンパイルエラーになる。

**このファイルは約800行しかない。部分読みせず、必ず一度に全体を読み込むこと。** なおこのファイルはライブラリの利用方法のみを扱う。カスタム層・出力層・オプティマイザ等を自作する場合は `docs/llms-custom.txt`（約600行）を追加で読むこと。

Kotlin Multiplatformライブラリ。JitPackからGradle依存として導入できる。

- 対応プラットフォーム: JVM / Android。Kotlin/Native（macOS / Linux / Windows）はJitPackでは配布されておらず、リポジトリをローカルで `publishToMavenLocal` した場合のみ利用できる。JS / wasm は非対応。
- `<version>` には最新リリースを指定する（https://jitpack.io/#Wansuko-cmd/knist または GitHub Releases で確認）。
- この文書は v0.0.32-alpha05 以降（2026-08 時点の main）の API を記述している。

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        maven { url = uri("https://jitpack.io") }
    }
}

// build.gradle.kts
dependencies {
    implementation("com.github.Wansuko-cmd.knist:network:<version>")
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:<version>")  // train / loss / expect が suspend 関数のため必須
}
```

注意: `com.github.Wansuko-cmd:knist` ではなく `com.github.Wansuko-cmd.knist:network` を使うこと。前者はJitPackのラッパーPOMであり、KMPのvariant選択が効かない。

## バックエンド設定

演算の実行バックエンドを切り替えられる。デフォルトは CPU（Rust ネイティブ）。どのバックエンドも `network` の依存に含まれるため、追加の Gradle 依存は不要。

| バックエンド | 生成関数 | import | 説明 | フォールバック |
|------------|--------|--------|------|--------------|
| CPU | `loadCPUBackend(fallback, maxReservedBytes = 4_000_000_000L, maxPoolBytes = maxReservedBytes)` | `com.wsr.knist.cpu.loadCPUBackend` | Rust ネイティブ CPU 実装 | 引数で指定 |
| GPU | `loadGPUBackend(fallback, maxReservedBytes = 4_000_000_000L, maxPoolBytes = maxReservedBytes, enableProfiler = false)` | `com.wsr.knist.gpu.loadGPUBackend` | WebGPU（wgpu）GPU 実装 | 引数で指定 |
| `KotlinBackend` | — | `com.wsr.knist.base.KotlinBackend` | 純 Kotlin 実装 | — |

呼び出し側で `loadCPUBackend` / `loadGPUBackend` を明示的に呼んでバックエンドを生成し、`Backend.set()` に渡す。

```kotlin
import com.wsr.knist.Backend
import com.wsr.knist.base.KotlinBackend
import com.wsr.knist.gpu.loadGPUBackend

Backend.set(loadGPUBackend(KotlinBackend))
```

`maxReservedBytes` / `maxPoolBytes` はいずれも CPU・GPU 共通で省略時は固定 4GB（JVM ヒープ・VRAM 連動のような自動デフォルトは無い）。
なお `maxReservedBytes` が効くのは JVM / Android のみで、Kotlin/Native では無視される。

- **`maxReservedBytes`**: 確保済みバッファの合計がこの値を超えている間、バッファを確保するたびに `System.gc()` が呼ばれる。attention 等で中間バッファが多いモデルでは閾値を超え続けて `System.gc()` が連発し、大幅な速度低下を招くことがある。
- **`maxPoolBytes`**: 解放済みバッファを再利用するプールが保持できる総バイト数の上限。省略時は `maxReservedBytes` と同じ値になる。

大きいモデルや大きいバッチで `System.gc()` の発火が頻発する場合は、モデルに応じて明示的に引き上げる
（例: `loadCPUBackend(KotlinBackend, maxReservedBytes = 10_000_000_000L)`）。

`loadCPUBackend` / `loadGPUBackend` はネイティブライブラリが利用不可の環境では自動的に `fallback`（通常 `KotlinBackend`）を返す。
※ GPUは不安定で、稀に実行速度が非常に遅くなることがある。その際にはCPUに書き換える。

## 基本的な使い方

### モデル構築

`Network.create(port(converter), optimizer, initializer) { input -> ... }` のブロックDSLでレイヤーを積み上げる。ブロックの最後に出力層（`softmaxWithLoss` 等）を呼ぶと、その戻り値がそのまま `Network` オブジェクトになる（末尾で `toNetwork()` のような変換を呼ぶ必要はない）。

`port(converter)` は `Converter<T>` を入力口に変換するだけで、`optimizer` / `initializer` は受け取らない。それらは `create()` の引数として渡す。

`Network.Src1.Sink1<I, O>` の `I`・`O` はバッチ全体の型。`Converter<T>` の `T` がそのままバッチ型として使われる。

```kotlin
import com.wsr.knist.network.Network
import com.wsr.knist.network.create
import com.wsr.knist.network.port

// Batch<IOType.D1> を直接渡す場合（RawD1 を使う）
val network: Network.Src1.Sink1<Batch<IOType.D1>, Batch<IOType.D1>> = Network.create(
    port = port(RawD1(32)),
    optimizer = AdamW(Scheduler.Fix(0.001f)),
    initializer = He(),
) { input ->
    input.affine(neuron = 256).bias().reLU()
        .affine(neuron = 10)
        .meanSquare()
}

// カスタムConverter を使う場合（例: List<List<Float>> → D2）
val network: Network.Src1.Sink1<List<List<Float>>, List<Int>> = Network.create(
    port = port(MyPixelConverter(28, 28)),
    optimizer = AdamW(Scheduler.Fix(0.001f)),
    initializer = He(),
) { input ->
    input.reshapeToD1()
        .affine(neuron = 10)
        .softmaxWithLoss(converter = { MyLabelConverter(inputI) })
}
```

戻り値の型は `Network.Src1.Sink1<I, O>`（入力1個・出力1個）。多入力・多出力にする場合は下の「多入力・多出力モデル」節を参照。

### Raw入力用の Batch の作り方

`RawD1` 等を使う場合、入力の `Batch<IOType.Dx>` は FloatArray から直接構築する。`value` にはバッチ全サンプルを行優先で連結した配列（長さ = バッチサイズ × 1サンプルの要素数）を渡す。

```kotlin
import com.wsr.knist.batch.Batch
import com.wsr.knist.core.IOType
import com.wsr.knist.base.data.DataBuffer

// バッチサイズ64・1サンプルの形状 [32] の D1 入力バッチ
val inputs: Batch<IOType.D1> = Batch(
    size = 64,
    shape = listOf(32),
    value = DataBuffer.create(FloatArray(64 * 32) { /* 値 */ 0f }),
)
// D2 は shape = listOf(i, j)、D3 は shape = listOf(i, j, k)
```

### 学習

`I` 自体がバッチ型なので、バッチ単位で渡す。`train` / `loss` / `expect` はすべて `suspend` 関数であり、コルーチンスコープ内から呼ぶことを想定している。いずれも `dispatcher` 引数（デフォルト: `Dispatchers.Default`）を取る。

`Network` はスレッドセーフ。ただし排他されるのは `train` 同士のみで、複数コルーチンから並列に `train` を呼んでも実行は1件ずつ直列化される。`loss` / `expect` は排他されず、`train` と並行して呼んでも、`loss` / `expect` 同士で並列に呼んでもブロックされない。

```kotlin
// suspend スコープ内での典型的な使い方
coroutineScope.launch {
    // ラベルを直接渡す（戻り値は IOType.D0.Global）
    val loss: IOType.D0.Global = network.train(input = inputs, label = labels)
    val lossValue: Float = loss.unwrap()  // Float として読み出す場合

    // ラベルジェネレータ（現在の出力を受け取って目標値を返す。DQN の Bellman ターゲット等に使える）
    val loss: IOType.D0.Global = network.train(input = inputs) { currentOutput -> modifiedOutput }
}
```

典型的なエポックループ（カスタム Converter 使用時の例。`I` = `List<List<Float>>`, `O` = `List<Int>`）:

```kotlin
runBlocking {
    repeat(epochs) {
        dataset.shuffled().chunked(batchSize).forEach { chunk ->
            network.train(
                input = chunk.map { it.pixels },
                label = chunk.map { it.label },
            )
        }
    }
}
```

### loss計算（逆伝播なし）

`train()` と同じ2バリアントがある。重みを更新せずに損失だけ得たい場合に使う。
順伝播は推論時と同じ経路で行われる（dropout はパススルーになる等）。

```kotlin
val loss: IOType.D0.Global = network.loss(input = inputs, label = labels)
val loss: IOType.D0.Global = network.loss(input = inputs) { currentOutput -> modifiedOutput }
```

### 推論

```kotlin
val result: O = network.expect(input = inputs)  // suspend。inputs: I（バッチ型）
```

戻り値は出力層の結果（`softmaxWithLoss` なら softmax 後の確率分布）を `Converter.decode` に通したもの。生の確率分布を使いたい場合（温度・top-k 等のサンプリングを自前で行う場合など）は、decode がそれを返すように Converter を実装する。

## port() ファクトリ関数

`Network.create(...)` の第一引数（多入力の場合は `port1` / `port2`）に渡す「入力口」を作る。次元(D1/D2/D3)は `Converter` のサブクラスで決まり、`port()` はオーバーロード解決でそれに応じた `Port<T, D>` を返す。`optimizer` / `initializer` はここでは渡さず `create()` 側の引数にする。

| 関数 | import | 引数 | 対応する次元 |
|------|--------|------|-------------|
| `port(converter: Converter.D1<T>)` | `com.wsr.knist.network.port` | 任意のConverter | D1 |
| `port(converter: Converter.D2<T>)` | 同上 | 任意のConverter | D2 |
| `port(converter: Converter.D3<T>)` | 同上 | 任意のConverter | D3 |

`Batch<IOType.Dx>` をそのまま入力する場合は、Raw系Converterを渡す（下記）。

| クラス | import | 対応する次元 |
|--------|--------|-------------|
| `RawD1(i)` | `com.wsr.knist.network.converter.raw.RawD1` | D1(i) |
| `RawD2(i, j)` | `com.wsr.knist.network.converter.raw.RawD2` | D2(i, j) |
| `RawD3(i, j, k)` | `com.wsr.knist.network.converter.raw.RawD3` | D3(i, j, k) |

```kotlin
port(RawD1(32))              // Port<Batch<IOType.D1>, GraphBuilder.Node.D1>
port(MyPixelConverter(28, 28)) // Port<List<List<Float>>, GraphBuilder.Node.D2>（MyPixelConverterがConverter.D2の場合）
```

## 多入力・多出力モデル

`create()` に `port` を複数渡すと、複数の入力口を持つモデルを構築できる。ブロックは入力の数だけノードを引数で受け取り、出力を複数返したい場合は末尾で `outputs(...)` を呼ぶ（出力1個の場合はそのブロックの戻り値がそのまま `Network` になる、単入力の場合と同じ省略ルール）。

戻り値の型は `Network.Src{入力数}.Sink{出力数}<...>`（現状 入力・出力とも最大2まで）。

```kotlin
// 2入力・2出力（two-tower風。2つのSourceを合流させたうえで2つのheadへ出力する例）
val network: Network.Src2.Sink2<Batch<IOType.D1>, Batch<IOType.D1>, Batch<IOType.D1>, Batch<IOType.D1>> =
    Network.create(
        port1 = port(RawD1(1)),
        port2 = port(RawD1(1)),
        optimizer = Sgd(scheduler = Scheduler.Fix(rate = 0.1f)),
        initializer = He(),
    ) { input1, input2 ->
        val trunk = add(input1.affine(neuron = 8), input2.affine(neuron = 8))
        val o1 = trunk.affine(neuron = 1).meanSquare()
        val o2 = trunk.affine(neuron = 1).meanSquare()
        outputs(o1, o2)
    }

// 呼び出し側は入力・ラベルの数だけ引数が増える
val (out1, out2) = network.expect(input1 = inputA, input2 = inputB)
network.train(input1 = inputA, input2 = inputB, label1 = labelA, label2 = labelB)
```

同じ次元の複数ノードを合流させる Join 関数は4種類ある。いずれも異なる `Source` に由来するノード同士でも合流できる。合流点（fan-out するノード）の逆伝播delta は、そこから消費するすべての経路（下流の複数の出力head 等）からの寄与の合計になる。

| 関数 | import | 形状の制約 | 説明 |
|------|--------|-----------|------|
| `add(vararg nodes)` | `com.wsr.knist.network.join.add.add` | 全ノード同一サイズ | 要素ごとの和 |
| `mul(vararg nodes)` | `com.wsr.knist.network.join.mul.mul` | 全ノード同一サイズ | 要素ごとの積 |
| `max(vararg nodes)` | `com.wsr.knist.network.join.max.max` | 全ノード同一サイズ | 要素ごとの最大値 |
| `concat(vararg nodes, axis?)` | `com.wsr.knist.network.join.concat.concat` | 連結軸以外は全ノード同一サイズ | 指定軸方向の連結（連結軸の出力サイズは各ノードのサイズの和）。D1 は `axis` 引数を取らない、D2/D3 は必須 |

`add` / `mul` / `max` は全ノードが同一サイズであることが前提で、違反するとモデル構築時に例外になる。`concat` のみ連結軸のサイズが異なるノード同士を連結できる（連結軸以外のサイズは揃っている必要がある）。

`train` / `loss` にはラベルジェネレータ版（現在の出力を受け取って目標値を返す）もあり、`Sink2`（2出力）モデルでも `label1` / `label2` の両方をラムダで渡せる。

`Sink2` 系の `train` / `loss` は `Pair<IOType.D0.Global, IOType.D0.Global>`（`sink1` 側・`sink2` 側の損失）を返す。

どの出力にも繋がっていない port を作ってもエラーにはならず、その入力は単に無視される。

## IOType 定義

| 型 | 形状 | 意味 |
|----|------|------|
| `D0` | スカラー | 損失値など単一値 |
| `D1(i)` | [i] | ベクトル |
| `D2(i, j)` | [i, j] | 行列 |
| `D3(i, j, k)` | [i, j, k] | 3次元テンソル |

各次元型には `Global` と `Local` の2サブクラスがあるが、**ライブラリを利用するだけなら区別を意識する必要はない**。`train` / `loss` 等の API が返すのはすべて `Global`。`Local` はカスタム層等を実装する場合にのみ現れる（`docs/llms-custom.txt` を参照）。

`IOType` をユーザーコードで明示的に解放する必要はない。バッファの解放は自動的に行われる。

`IOType.D0.Global` から `Float` を取り出すには `.unwrap()` を使う（import: `com.wsr.knist.core.unwrap`）:

```kotlin
val lossValue: Float = loss.unwrap()
```

## 全層一覧（import パス付き）

重みを持つレイヤーの factory 関数（`affine` / `bias` / `scale` / `convD1` / `convD2` / `attention` / `tokenEmbedding` / `positionEmbedding`）は、表に記載の引数に加えて `optimizer` / `initializer` を省略可能引数として取り、層ごとに個別指定できる（詳細は Optimizer 節）。`minMaxNorm` は名前が似ているが重みを持たない層で、`optimizer` / `initializer` は取らない。

さらに**すべての**レイヤーの factory 関数は `id: String`（省略時はランダム UUID）を省略可能引数として取る。`id` は層（`Process`）の公開プロパティとして保持され、`replace`（層の差し替え・Optimizer の差し替え / 凍結）の `condition` で特定の層を狙い撃ちするのに使える（「モデルの改修」節を参照）。

### 畳み込み・プーリング

| 関数 | import | 入力 | 出力 | デフォルト値 |
|------|--------|------|------|-------------|
| `convD1(filter, kernel, stride?, dilation?, padding?)` | `com.wsr.knist.network.process.compute.conv.convD1` | D2(i, j) | D2(filter, outJ) | stride=1, dilation=1, padding=0 |
| `convD2(filter, kernel, stride?, dilation?, padding?)` | `com.wsr.knist.network.process.compute.conv.convD2` | D3(i, j, k) | D3(filter, outJ, outK) | stride=1, dilation=1, padding=0 |
| `maxPool(size, stride?, padding?)` | `com.wsr.knist.network.process.compute.pool.maxPool` | D2(i, j) | D2(i, outJ) | stride=size, padding=0 |
| `maxPool(size, stride?, padding?)` | `com.wsr.knist.network.process.compute.pool.maxPool` | D3(i, j, k) | D3(i, outJ, outK) | stride=size, padding=0 |

conv の出力サイズ: `out = (size - kernelSize + 2 * padding) / stride + 1`（`kernelSize = (kernel - 1) * dilation + 1`。dilation=1 なら kernelSize=kernel）
制約: `(size - kernelSize + 2 * padding) % stride == 0` であること。convD1 / convD2 とも違反するとモデル構築時に例外（convD2 は j・k 両方をチェックする）
maxPool の出力サイズ: `out = (j + 2*padding - size) / stride + 1`。`stride < size` とすると重複窓（overlapping pooling）になる
制約: maxPool は `(j + 2*padding - size) % stride == 0` でなければモデル構築時に例外（D3 は j・k 両方）

### パディング

| 関数 | import | 入力 | 出力 | デフォルト値 |
|------|--------|------|------|-------------|
| `padding(axis, left?, right?)` | `com.wsr.knist.network.process.compute.padding.padding` | D2(i, j) | axis=0: D2(i+left+right, j) / axis=1: D2(i, j+left+right) | left=0, right=0 |

指定軸の前後にゼロパディングを追加する（D2 のみ。axis: 0=i方向, 1=j方向。それ以外の axis は構築時エラー）。conv の `padding` 引数が両側均等・全軸一律なのに対し、こちらは軸と左右量を個別に指定できる。逆伝播ではパディング部分の delta は切り捨てられる。

### 全結合・変換系

| 関数 | import | 入力 | 出力 |
|------|--------|------|------|
| `affine(neuron)` | `com.wsr.knist.network.process.compute.affine.affine` | D1(n) | D1(neuron) |
| `affine(neuron)` | `com.wsr.knist.network.process.compute.affine.affine` | D2(i, j) | D2(i, neuron) |
| `bias()` | `com.wsr.knist.network.process.compute.bias.d1.bias` | D1(n) | D1(n) |
| `bias(axis?)` | `com.wsr.knist.network.process.compute.bias.d2.bias` | D2(i, j) | D2(i, j) |
| `bias(axis?)` | `com.wsr.knist.network.process.compute.bias.d3.bias` | D3(i, j, k) | D3(i, j, k) |
| `scale()` | `com.wsr.knist.network.process.compute.scale.d1.scale` | D1(n) | D1(n) |
| `scale(axis?)` | `com.wsr.knist.network.process.compute.scale.d2.scale` | D2(i, j) | D2(i, j) |
| `scale(axis?)` | `com.wsr.knist.network.process.compute.scale.d3.scale` | D3(i, j, k) | D3(i, j, k) |

D2/D3 の `bias` / `scale` の `axis`: null=全体, 0=i方向, 1=j方向（D3はさらに 2=k方向）

D1とD2で同名関数を両方 import する場合、Kotlin はレシーバー型で自動解決する:
```kotlin
import com.wsr.knist.network.process.compute.bias.d1.bias
import com.wsr.knist.network.process.compute.bias.d2.bias  // 同名でも競合しない
```

### Attention

| 関数 | import | 入力 | 出力 |
|------|--------|------|------|
| `attention(numOfHeads, dim?, biases?, optimizer?, initializer?)` | `com.wsr.knist.network.process.compute.attention.attention` | D2(i, j) | D2(i, j) |

デフォルト値: `dim = inputJ / numOfHeads`（整数除算）, `biases = { this }`（バイアスなし）
制約: j は numOfHeads で割り切れるようにすること。割り切れなくてもエラーにはならないが、デフォルトの `dim` が切り捨てられ、内部次元（numOfHeads × dim）が j より小さいモデルが黙って出来上がる
Self-attention 専用（Q・K・V はすべて同一の入力から計算される）。Q/K/V/O の射影にバイアス項は付かない。

`biases` ラムダで `AttentionBiasD2Builder` をチェーンして適用するバイアスを指定する。

| メソッド | 説明 |
|---------|------|
| `causal()` | Causal mask（未来トークンへの注目を -1e9 でマスク） |
| `mask(node: GraphBuilder.Node.D1, value: Float)` | Padding mask（`node` が指すグラフ上の任意ノードの値が `value` の位置を -1e9 でマスク） |
| `alibi()` | ALiBi（ヘッドごとに異なる傾きで距離に比例した罰則を加算） |

`mask` は `node` に渡した **D1 のトークンID列を持つノード**（グラフ中の任意のノード。ネットワーク全体の入力に限らない）を参照する。渡したノードの出力の長さが attention の系列長と一致している場合のみ使える（一致しない場合は実行時エラー）。`create()` ブロック内で入力ノード自体（またはその手前で作った別のノード）をそのまま渡せる。

```kotlin
// Causal のみ
input.attention(numOfHeads = 8, biases = { causal() })

// Causal + Padding mask（input はブロックの引数として渡ってくるノード）
input.attention(numOfHeads = 8, biases = { causal().mask(input, 0f) })

// ALiBi + Padding mask
input.attention(numOfHeads = 8, biases = { alibi().mask(input, 0f) })
```

### スキップ接続

| 関数 | import | 制約 |
|------|--------|------|
| `skip { ... }` | `com.wsr.knist.network.process.compute.skip.skip` | ブロック内の出力が入力と同サイズであること |

`huber` デフォルト値: `threshold=1f`
`|diff| < threshold` では二乗誤差、`|diff| >= threshold` では絶対誤差（Huber損失）として扱う。

`softmaxWithLoss` デフォルト値: `temperature=1f`
`temperature` は**構築時に固定**され、学習・推論の両方の softmax に適用される。構築後・読み込み後に変更する手段は無いため、推論時に温度を変えたい場合はモデルを構築し直す必要がある。
`softmaxWithLoss` の `converter` ラムダ内では `inputI` が参照可能

`softmaxWithLoss` の D2 版・D3 版は `axis: Int? = null` を取る。`null`（デフォルト）は全次元をフラット化した1グループとして softmax を計算し、`0`〜`inputの次元数-1`を指定するとその軸方向にのみ softmax を計算する（D2 は `0, 1`、D3 は `0, 1, 2` が有効値）。範囲外の値を渡すと構築時に例外になる。D1 版は次元が1つしか無いため `axis` は無い。

ラベルのある行を丸ごとロス計算から除外したい場合（パディング等）は、`maskValue` のような専用パラメータは無く、Converter の `encode` 側でその行を全ゼロベクトルとして出力する。**D2 版・D3 版の** `softmaxWithLoss` は合計が 0 のラベルを自動的に除外する（`axis` で指定した軸ごとの合計が対象。D1 版にこの除外は無い）。

## Converter（入出力変換器）

ユーザーデータと内部 IOType の変換を担う。`port()` ファクトリ関数と、`softmaxWithLoss` 等の出力層関数の両方に渡せる。

`Converter<T>` の型パラメータ `T` はバッチ全体の型。`encode(input: T)` がバッチを受け取り、`decode` がバッチを返す。これがそのまま `Network.Src1.Sink1<I, O>` の `I`・`O` になる。

### 組み込みConverter

| クラス | import | 入力型(T) | 次元 |
|--------|--------|----------|------|
| `RawD1(outputI)` | `com.wsr.knist.network.converter.raw.RawD1` | `Batch<IOType.D1>` | D1 |
| `RawD2(outputI, outputJ)` | `com.wsr.knist.network.converter.raw.RawD2` | `Batch<IOType.D2>` | D2 |
| `RawD3(outputI, outputJ, outputK)` | `com.wsr.knist.network.converter.raw.RawD3` | `Batch<IOType.D3>` | D3 |

Raw 系は変換なし（`Batch<IOType.Dx>` をそのまま渡す）。カスタム型を使う場合はカスタム Converter を実装する。

### カスタムConverter実装に必要な import

```kotlin
import com.wsr.knist.batch.Batch                  // Batch<T>
import com.wsr.knist.batch.shape.toList           // Batch.toList()
import com.wsr.knist.core.IOType                  // IOType.D1 / D2 / D3
import com.wsr.knist.batch.reduction.maxIndex     // Batch<IOType.D1>.maxIndex() 等（decode で使う。IOType 単体用は com.wsr.knist.core.reduction.maxIndex）
import com.wsr.knist.base.data.DataBuffer         // DataBuffer.create(floatArray)
import com.wsr.knist.network.converter.Converter  // Converter.D1<T> / D2<T>
```

### カスタムConverter実装例

**出力ラベル用（List<Int> → One-hot）**

T はバッチ型なので `List<Int>`（バッチ分のラベルをまとめて受け取る）。

```kotlin
@Serializable
data class LabelConverter(override val outputI: Int) : Converter.D1<List<Int>>() {
    override fun encode(input: List<Int>): Batch<IOType.D1> {
        val value = FloatArray(input.size * outputI)
        input.forEachIndexed { batchIndex, label ->
            value[batchIndex * outputI + label] = 1f
        }
        return Batch(size = input.size, shape = listOf(outputI), value = DataBuffer.create(value))
    }
    override fun decode(input: Batch<IOType.D1>): List<Int> =
        input.maxIndex().value.toFloatArray().map { it.toInt() }
}
```

**入力特徴量用（List<List<Float>> → D2）**

```kotlin
@Serializable
data class PixelConverter(override val outputI: Int, override val outputJ: Int) : Converter.D2<List<List<Float>>>() {
    override fun encode(input: List<List<Float>>): Batch<IOType.D2> {
        val value = input.flatten().toFloatArray()
        return Batch(size = input.size, shape = listOf(outputI, outputJ), value = DataBuffer.create(value))
    }
    override fun decode(input: Batch<IOType.D2>): List<List<Float>> =
        input.value.toFloatArray().toList().chunked(outputI * outputJ)
}
```

保存・読み込みを使う場合は `@Serializable` を付けて登録する（ビルド設定は「モデルの保存・読み込み」節を参照）:
```kotlin
NetworkSerializer.apply { register(LabelConverter::class) }
```

## Optimizer

| クラス | import | 追加パラメータ |
|--------|--------|--------------|
| `Sgd(scheduler)` | `com.wsr.knist.network.optimizer.sgd.Sgd` | — |
| `Momentum(scheduler, momentum?)` | `com.wsr.knist.network.optimizer.momentum.Momentum` | momentum=0.9f |
| `RmsProp(scheduler, rms?)` | `com.wsr.knist.network.optimizer.rms.RmsProp` | rms=0.9f |
| `Adam(scheduler, momentum?, rms?)` | `com.wsr.knist.network.optimizer.adam.Adam` | momentum=0.9f, rms=0.999f |
| `AdamW(scheduler, momentum?, rms?, decay?)` | `com.wsr.knist.network.optimizer.adam.AdamW` | momentum=0.9f, rms=0.999f, decay=0.01f |
| `Freeze` | `com.wsr.knist.network.optimizer.freeze.Freeze` | —（引数を取らない object） |

`Freeze` は重みを一切更新しない特殊な Optimizer で、層の凍結に使う（「モデルの改修」節の「Optimizer の差し替え・層の凍結」を参照）。scheduler / 共通オプションも取らない。

共通オプション:

- `maxNorm`: 勾配クリッピング。勾配の L2 ノルムが `maxNorm` を超えた場合にスケールダウンする
- `stepUnit`: **勾配累積**。`train()` `stepUnit` 回分の勾配を内部に累積し、その平均勾配で1回だけ重みを更新する。累積中の `train()` では重みは変化しない。Scheduler の step も実際の重み更新1回につき1進む

Optimizer / Initializer は `Network.create()` の引数として渡したものがデフォルトとして全層に配られるが、学習可能なレイヤーの factory 関数（`affine` / `bias` / `scale` / `convD1` / `convD2` / `attention` / `tokenEmbedding` / `positionEmbedding`）は `optimizer` / `initializer` 引数で層ごとに上書きできる。なお `bias` の initializer デフォルトは `Fixed(0f)`、`scale` は `Fixed(1f)`。

`Network.create()` に渡した Optimizer / Initializer は `Network` 自身にも保持され、`toJson()` / `toCbor()` で保存される。「モデルの改修」節の `replace` はこれをデフォルト値として使う。このデフォルトは `replace` で層や Optimizer を差し替えても変わらない（あくまで構築時に決まる値）。

`AdamW` の `decay` は bias / scale を含む**全パラメータに一律に適用される**。特定の層を weight decay から除外したい場合は、その層の `optimizer` 引数に decay の無い Optimizer（`Adam` 等）を個別に渡す。

### Scheduler

| クラス | import | 説明 |
|--------|--------|------|
| `Scheduler.Fix(rate)` | `com.wsr.knist.network.optimizer.Scheduler` | 固定学習率 |
| `Scheduler.Step(rate, gamma, stepCount)` | 同上 | Nステップごとに rate *= gamma |
| `Scheduler.MultiStep(rate, gamma, milestones)` | 同上 | 指定ステップで rate *= gamma |
| `Scheduler.CosineAnnealing(minRate, maxRate, stepSize, warmUp?, initialRate?)` | 同上 | 線形ウォームアップ→コサインアニーリング（warmUp=0, initialRate=minRate） |

Scheduler が受け取る step は「そのパラメータの実際の重み更新回数」（`stepUnit` 回の `train()` につき 1）で、パラメータごとに独立してカウントされる。`stepUnit = 1`（デフォルト）なら実用上は「`train()` の呼び出し回数」と読み替えてよい（`stepSize` / `warmUp` / `stepCount` / `milestones` は重み更新回数を基準に設定する）。

## モデルの保存・読み込み

`toJson()` / `toCbor()` は `Network.Src1.Sink1` 等の各facade型のメンバー関数、`fromJson()` / `fromCbor()` はそれぞれのfacade型（`Network.Src1.Sink1` / `Network.Src2.Sink1` 等）の `Companion` 関数として存在する（`Network.Companion` 直下ではない）。いずれも import 不要。

保存されるのはモデル構造・重みに加えて、**Optimizer の内部状態（Adam のモーメント等）と Scheduler の進行位置**、および `Network` がデフォルトとして保持する Optimizer / Initializer も含まれる。読み込み後に学習を再開すると保存時のスケジュールの続きから進む。構築後・読み込み後に学習率や Optimizer を差し替えたい場合は「モデルの改修」節の `replace` を使う（層の凍結・差し替え・Source / Sink の差し替えも同節を参照）。

`fromJson` / `fromCbor` の型パラメータ `I`・`O` は実行時に検証されない。保存時と異なる型を指定しても読み込み自体は成功し、`expect` / `train` の呼び出し時に ClassCastException になるため注意。

カスタムConverterを使っている場合は保存前に登録が必要。

### カスタムConverterを保存する場合のビルド設定

組み込みConverter（`RawD1` 等）のみ使う場合は不要。カスタムConverterを保存・読み込みする場合のみ、以下の設定が必要。

```kotlin
// build.gradle.kts
plugins {
    kotlin("plugin.serialization")
}

dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-core:<version>")
}
```

設定後、カスタムConverter に `@Serializable` を付けて登録する。登録はアプリ起動時などに**各クラスにつき一度だけ**行えばよい（モデルを生成するたびに呼ぶ必要はない）：

```kotlin
import com.wsr.knist.network.NetworkSerializer

NetworkSerializer.apply {
    register(MyConverter::class)  // カスタムConverterのみ登録。組み込みは不要
}
```

```kotlin
// 読み込み（facade型に応じて Network.Src1.Sink1 / Network.Src2.Sink1 等を使う）
val network: Network.Src1.Sink1<I, O> = Network.Src1.Sink1.fromJson(json)
```

```kotlin
// 保存

val network: Network.Src1.Sink1<I, O> = Network.Src1.Sink1.fromJson(source)
```

### CBOR形式（バイナリ）

```kotlin
// 保存
val bytes: ByteArray = network.toCbor()
network.toCbor(sink)  // Sink版

// 読み込み
val network: Network.Src1.Sink1<I, O> = Network.Src1.Sink1.fromCbor(bytes)
val network: Network.Src1.Sink1<I, O> = Network.Src1.Sink1.fromCbor(source)  // Source版
```

### クローン

```kotlin
val copy: Network.Src1.Sink1<I, O> = network.clone()
```

重みを含む完全なコピーが得られる。CBOR シリアライズを経由するため、カスタム Converter を使う場合は事前に `NetworkSerializer.register()` が必要。

## モデルの改修（層の凍結・差し替え、Source / Sink の差し替え）

構築済み・`fromJson` / `fromCbor` で読み込み済みの `Network` に対して、転移学習・ファインチューニング目的で層の凍結や差し替えができる。

**いずれの操作も元の `network` は変更せず、新しい `Network` を返す。** 返された `Network` の層・重みは元の `network` とは独立したコピーになる。`clone()` と同じく CBOR シリアライズを経由するため、カスタム Converter を使っている場合は事前に `NetworkSerializer.register()` が必要。

### Optimizer の差し替え・層の凍結

学習率の変更・Optimizer の切り替え・層の凍結は、いずれも「`condition` に一致した層の Optimizer を、渡したファクトリから作り直す」一つの操作で行う。重みは保持されるが、Optimizer の内部状態（Adam のモーメント等）と Scheduler の進行位置はリセットされる。

```kotlin
// 読み込んだモデルを低い学習率で微調整する（重みは保持、モーメント・Scheduler 位置はリセット）
val tuned: Network.Src1.Sink1<I, O> = network.replace(condition = { true }, optimizer = AdamW(Scheduler.Fix(0.0001f)))

// 層の凍結: Freeze（重みを更新しない Optimizer）を渡す
val frozen: Network.Src1.Sink1<I, O> = network.replace(condition = { it.id == "backbone" }, optimizer = Freeze)

// 解凍: 通常の Optimizer を渡し直す（新品の状態で学習が再開される）
val unfrozen: Network.Src1.Sink1<I, O> = frozen.replace(condition = { it.id == "backbone" }, optimizer = AdamW(Scheduler.Fix(0.00001f)))
```

- `Freeze` で凍結された層は重みの更新だけが行われなくなる。逆伝播の delta は通常通り流れるため、凍結した層より前段の学習は継続できる
- 重みを持たない層（活性化関数・reshape 等）では何も起きないため、`condition = { true }` で全層を対象にして問題ない
- カスタム層は `update(optimizer)` を override していないと反応しない（`docs/llms-custom.txt` を参照）

### 中間層の差し替え

`replace<T>` で、型と条件にマッチする層を `GraphBuilder` の DSL でまるごと差し替えられる。関数名は `T` の種類によらず `replace`。新しい `Network` を返す。

```kotlin
val newNetwork: Network.Src1.Sink1<I, O> = network.replace<AffineD2>(
    optimizer = AdamW(Scheduler.Fix(0.0001f)),  // 省略時は network が保持する Optimizer を使う
    initializer = He(),                          // 省略時は network が保持する Initializer を使う
    condition = { it.outputI == 256 },           // id で特定する場合: { it.id == "..." }
) { old ->
    // this: GraphBuilder.Node.D2（affine 等の DSL がそのまま使える）
    // old: マッチした元の層（T 型。元の層のプロパティを参照したい場合に使う）
    affine(neuron = 512).bias().reLU()
}
```

- `condition` に一致した各層を、`block` が返す `GraphBuilder.Node.Dx` までの層列で置き換える
- 置き換え後の層列の入力形状・出力形状は、元の層の入力形状・出力形状と一致していなければならず、一致しない場合は例外になる
- `block` が何も層を追加しない場合（元の `GraphBuilder.Node.Dx` をそのまま返す場合）、その層は削除されるだけになる。削除できるのは入力形状と出力形状が一致している層（活性化関数・`bias` 等）のみで、一致しない層（`affine` 等）を削除しようとすると例外になる
- `T`（マッチさせる層の型）は `Compute.D1` / `Compute.D2` / `Compute.D3`、または `Reshape.D1ToD2` / `D1ToD3` / `D2ToD1` / `D2ToD3` / `D3ToD1` / `D3ToD2` のいずれかのサブタイプである必要がある。`T` の次元遷移によってどのオーバーロードが選ばれるかが決まる

Reshape 系の層（`tokenEmbedding` / `reshapeToDx` / `globalAverageToDx` 等）を対象にする場合、`block` は元の層と同じ次元遷移で終わる必要がある（例: `Reshape.D1ToD2` なら this は `GraphBuilder.Node.D1`、戻り値は `GraphBuilder.Node.D2`）。戻り値の型で強制されるため、Reshape 系では `block` を空にする（層を削除するだけにする）ことはできない。

```kotlin
// 学習済みモデルの tokenEmbedding を語彙サイズだけ変えて差し替える（語彙の転移）
// vocabSize は出力形状 D2(i, tokenSize) に現れないため、tokenSize を保てば形状チェックを通る
val newNetwork: Network.Src1.Sink1<I, O> = network.replace<TokenEmbeddingD1ToD2>(
    condition = { true },
) { old ->
    tokenEmbedding(vocabSize = 5000, tokenSize = old.outputJ)
}
```

### Source（入力）の差し替え

`I` を変えたい場合（入力の前処理・Converterを変える等）に使う。層はそのまま、Converterだけ差し替わる。単入力なら `replaceSource`、多入力（`Src2` 系）なら対象のportごとに `replaceSource1` / `replaceSource2` を呼ぶ。

```kotlin
val network2: Network.Src1.Sink1<NewInput, O> = network.replaceSource(newInputConverter)

// 2入力モデルの片方だけ差し替える場合
val network3: Network.Src2.Sink1<NewInput1, I2, O> = network.replaceSource1(newInputConverter)
```

新しい `Network` を返す（元の `network` は変更されない）。層・重みは元の `network` とは独立したコピーになる（共有されない）。

### Sink（出力）の差し替え

出力層（`softmaxWithLoss` 等）から手前の層列をまとめて組み直したい場合に使う。中間層の差し替え（`replace<T>`）と違い、**グラフ末尾の Compute ノードから新しい出力までを丸ごと再構築する**（新しい層を挟む・出力の型 `O` を変える、のどちらもこの1回でできる）。単一出力なら `replaceSink`、`Sink2` 系なら対象headごとに `replaceSink1` / `replaceSink2` を呼ぶ。`T`（末尾層の出力形状。`Output.D1` / `Output.D2` / `Output.D3`）で受け取れる次元を指定する。`Sink3` 系では `replaceSink1` / `replaceSink2` / `replaceSink3` を呼ぶ。

```kotlin
// temperatureだけ変えたい場合。既存の末尾層の出力形状(D1)からやり直す
val network5: Network.Src1.Sink1<I, O> = network.replaceSink<Output.D1, O> {
    // this: GraphBuilder.Node.D1（末尾のComputeノードの出力形状から再開する）
    softmaxWithLoss(temperature = 0.5f, converter = { LabelConverter(inputI) })
}

// Oも変え、間に新しい層を挟みつつ差し替える場合
val network6: Network.Src1.Sink1<I, NewLabel> = network.replaceSink<Output.D1, NewLabel>(
    optimizer = AdamW(Scheduler.Fix(0.0001f)),  // 省略時は network が保持する Optimizer を使う
    initializer = He(),
) {
    affine(neuron = 512).bias().reLU()
        .softmaxWithLoss(converter = { NewLabelConverter(10) })
}
```

## 典型的な構成パターンとIOの流れ

完全に動作するコードはリポジトリの `sample/` にある:

- MNIST（3層MLP）: `sample/src/commonMain/kotlin/dataset/mnist/MnistUtils.kt`（`PixelConverter` / `LabelConverter` の実装は同ディレクトリの `MnistConverter.kt`）
- TinyStories（Transformer言語モデル）: `sample/src/commonMain/kotlin/dataset/stories/TinyStoriesUtils.kt`（`WordsD1` / `WordD2` の実装も同ディレクトリ）

### MLP（全結合分類）

```
Network.create(port(converter), optimizer, initializer) { input -> } → D1(n)
  → affine(256) → bias() → reLU()          → D1(256)
  → affine(10)                              → D1(10)
  → softmaxWithLoss(converter = { ... })   → Network.Src1.Sink1<Input, Label>
```

### 画像分類（CNN）

`PixelConverter` / `LabelConverter` はカスタム実装（Converter実装例を参照）。

```
Network.create(port(PixelConverter(28,28)), ...)  → D2(28, 28)   // Network.Src1.Sink1<List<List<Float>>, List<Int>>
  → convD1(32, kernel=3, padding=1)         → D2(32, 28)   // outY=(28-3+2)/1+1=28
  → bias() → reLU()
  → maxPool(size=2)                         → D2(32, 14)   // 28/2=14
  → convD1(64, kernel=3, padding=1)         → D2(64, 14)
  → bias() → reLU()
  → maxPool(size=2)                         → D2(64,  7)
  → reshapeToD1()                           → D1(448)      // 64*7=448
  → layerNorm() → affine(128) → bias() → reLU()
  → affine(10)
  → softmaxWithLoss(converter = { LabelConverter(inputI) })
```

### Transformer言語モデル

`WordsD1` / `WordD2` はカスタム実装（組み込みには含まれない）。

```
Network.create(port(wordsD1(maxLength=128, words=...)), ...)  → D1(128)  // Network.Src1.Sink1<List<List<String>>, List<List<String>>>
  → tokenEmbedding(vocabSize=3000, 256)     → D2(128, 256)
  → positionEmbedding()
  → repeat(4) {
      skip { layerNorm(1).scale(1).bias(1).attention(4, biases = { causal() }).dropout(0.9f) }
      skip { layerNorm(1).scale(1).bias(1).affine(1024).bias(1).swish().affine(256).bias(1).dropout(0.9f) }
    }
  → layerNorm(1).scale(1).bias(1)
  → affine(3000)
  → softmaxWithLoss(converter = { WordD2(words, 128, 1) })
```

## IOScope

`IOScope` は演算中の中間バッファのライフタイムを管理する仕組み。学習・推論では自動的に使われるため、**ライブラリを利用するだけなら意識する必要はない**。カスタム層（`Compute`）・出力層（`Output`）・オプティマイザ（`Optimizer`）を実装する場合は `docs/llms-custom.txt` を参照。
