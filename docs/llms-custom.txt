# knist カスタム実装リファレンス

**このファイルは約600行しかない。部分読みせず、必ず一度に全体を読み込むこと。** ライブラリの基本的な利用方法（モデル構築・学習・推論・保存）は `docs/llms-usage.txt` を参照。

knist の拡張ポイントは6つある。カスタム実装はいずれも `@Serializable` を付けること。`toJson()` / `toCbor()` だけでなく `clone()` / `replace()` 系も CBOR シリアライズを経由するため、付けないとそれらがすべて使えない。

カスタム実装は `NetworkSerializer.register()` に登録することで保存・読み込みに対応する。登録先は引数の型から自動で解決される（`Compute` は `Process` として、`Optimizer.D1` 〜 `D4` はそれぞれの次元として登録される）。対応しているのは `Process`（= `Compute`）・`Join`・`Output`・`Optimizer`・`Optimizer.D1` 〜 `D4`・`WeightInitializer`・`AttentionBiasD2`・`Converter`。

- `Compute`（`Process` の実装） — 中間層（順伝播・逆伝播）
- `Join` — 複数ノードの合流層（組み込みの `add` / `mul` / `max` / `concat` と同枠）
- `Output` — 出力層（損失計算）
- `Optimizer` — 重み更新アルゴリズム
- `WeightInitializer` — 重み初期化
- `AttentionBiasD2` — アテンションバイアス（Causal・Padding・ALiBi 等）

## IOScope と Global / Local

`IOScope` は演算中の中間バッファのライフタイムを管理する仕組み。スコープ内で生成された中間 `IOType` は、スコープ終了時に自動的に解放される。各 `IOType.Dx` には2つのサブクラスがある:

| サブクラス | 意味 |
|-----------|------|
| `IOType.Dx.Global` | スコープ外の値。自動解放されない（重み・API の戻り値など） |
| `IOType.Dx.Local` | `IOScope` 内の中間値。スコープ終了時に自動解放される |

`IOScope` 外で演算すると `Global` が、スコープ内（`with(ioScope) { }` または `IOScope.launch { }` 内）で演算すると `Local` が返る。
`Global` はスコープによる自動解放の対象外というだけで、明示的な解放は不要（参照が切れれば GC によって回収される）。

`IOType` / `Batch` の演算は `IOScope` のメンバー拡張関数なので、`IOScope` がレシーバーになっている場所でしか呼べない。

`Compute.expect` / `Compute.train` / `Output.expect` / `Output.train` / `Optimizer.adapt` はいずれも `IOScope` をレシーバーとして受け取るため、これらの実装ブロック内では演算をそのまま呼べる。`IOScope.launch` を明示的に呼ぶ必要はない。

```kotlin
override fun IOScope.expect(input: Batch<IOType.D1>, env: GraphEnv): Batch<IOType.D1> {
    val a = input + weight   // IOScope レシーバーがあるので直接呼べる
    return a * 2f
}
```

演算の結果は `IOType.Dx.Local` として返る。中間値のバッファはスコープ終了時に自動解放される。
保持し続けたい値（重み等）は `toGlobal()` で `Global` に昇格させてからフィールドに保存する。

```kotlin
// train 内での重み更新パターン
weight = optimizer.adapt(weight = weight, dw = delta).toGlobal()
```

## Batch<T>

`Batch<T : IOType>` は同一形状の `IOType` を複数まとめたバッチコンテナ。

```kotlin
class Batch<out T : IOType>(
    internal val value: DataBuffer,  // バッチ全体のデータを連続メモリで保持（外部からは unwrap() で FloatArray として取り出す）
    val size: Int,          // バッチサイズ
    val shape: List<Int>,   // 1要素の形状
)
```

### 要素アクセス

```kotlin
val element: T = batch[i]          // i番目の IOType を取り出す
val list: List<T> = batch.toList() // 全要素をリスト化（Converter の decode で使う）
```

### 生成

```kotlin
// IOType を直接並べて作る（テスト等で便利）
val batch = Batch.of(iotype1, iotype2, iotype3)

// IOScope 内では factory 関数で直接生成できる（結果は Local）。size はバッチサイズ
context(ioScope)
val batch: Batch<IOType.D1.Local> = Batch.d1(size = 4, i = 10) { 0f }
val batch: Batch<IOType.D2.Local> = Batch.d2(size = 4, i = 3, j = 5) { _, _ -> 0f }
```

### バッチ集約

```kotlin
// バッチ方向の平均を取って IOType に変換（Optimizer の dw 計算で使う）
val avg: IOType.D1 = batchOfD1.batchAverage()

// 要素ごとの平均を Batch で返す
val avg: Batch<IOType.D0> = batchOfD1.average()
```

## Compute（カスタム層）

`com.wsr.knist.network.process.Compute` の `D1` / `D2` / `D3` を継承する。

override 必須の抽象プロパティ:

- 入力形状: `inputI`（D1）、`inputI` / `inputJ`（D2）、`inputI` / `inputJ` / `inputK`（D3）
- 出力形状: `outputI`（D1）、`outputI` / `outputJ`（D2）、`outputI` / `outputJ` / `outputK`（D3）
- `id: String` — 層の識別子。`Network.replace` の `condition` から参照される。`Uuid.random().toString()` をデフォルト値にするのが組み込み層と同じ慣例（import: `kotlin.uuid.Uuid`）

`inputShape` / `outputShape` はこれらから自動導出される（override 不要）。

### Compute.D1

```kotlin
@Serializable
class MyLayerD1 internal constructor(
    override val inputI: Int,
    override val id: String = Uuid.random().toString(),
    // 重みがある場合: private var weight: IOType.D1.Global
) : Compute.D1() {

    override val outputI: Int get() = inputI  // 形状を変えない層の場合

    // 推論（勾配不要）
    override fun IOScope.expect(input: Batch<IOType.D1>, env: GraphEnv): Batch<IOType.D1> {
        return input + 1f  // IOType / Batch の演算はここで直接呼べる
    }

    // 学習（calcDelta に出力を渡すと upstream の delta が返ってくる）
    override fun IOScope.train(
        input: Batch<IOType.D1>,
        env: GraphEnv,
        calcDelta: IOScope.(Batch<IOType.D1>) -> Batch<IOType.D1>,
    ): Batch<IOType.D1> {
        val output = input + 1f
        val delta = calcDelta(output)
        // 重みの勾配計算・更新はここで行う
        return delta  // 入力方向への delta を返す
    }
}
```

### Compute.D2

```kotlin
@Serializable
class MyLayerD2 internal constructor(
```

### GraphBuilder.Node への登録

```kotlin
fun GraphBuilder.Node.D1.myLayer(id: String = Uuid.random().toString()) =
    addCompute(MyLayerD1(inputI = inputI, id = id))

fun GraphBuilder.Node.D2.myLayer(id: String = Uuid.random().toString()) =
    addCompute(MyLayerD2(inputI = inputI, inputJ = inputJ, outputI = inputI, outputJ = inputJ, id = id))
```

`inputI`（D1）・`inputI` / `inputJ`（D2）・`inputI` / `inputJ` / `inputK`（D3）が前の層の出力サイズ。
`optimizer` / `initializer` は `GraphBuilder.Node.Dx` のプロパティとして参照できる（`this.optimizer` / `this.initializer`）。`GraphBuilder.Node.Dx` は型パラメータを持たない（`I`・`O` は `create()` の外枠でのみ扱われる）。

### 重みを持つ層の実装例

```kotlin
@Serializable
class WeightedD1 internal constructor(
    override val inputI: Int,
    private var optimizer: Optimizer.D1,  // update で差し替えるため var
    private var weight: IOType.D1.Global,  // Global で保持する
    override val id: String = Uuid.random().toString(),
) : Compute.D1() {

    override val outputI: Int get() = inputI

    override fun IOScope.expect(input: Batch<IOType.D1>, env: GraphEnv): Batch<IOType.D1> =
        input + weight

    override fun IOScope.train(
        input: Batch<IOType.D1>,
        env: GraphEnv,
        calcDelta: IOScope.(Batch<IOType.D1>) -> Batch<IOType.D1>,
    ): Batch<IOType.D1> {
        val output = input + weight
        val delta = calcDelta(output)
        // optimizer.adapt はスコープが必要なので context(scope: IOScope) で呼ばれる
        weight = optimizer.adapt(weight = weight, dw = delta).toGlobal()
        return delta
    }

    // Network.replace(condition, optimizer) による Optimizer 差し替え・凍結に対応する場合は override する（デフォルトは何もしない）
    override fun update(optimizer: Optimizer) {
        this.optimizer = optimizer.d1(inputI)  // 自層の重み形状で作り直す
    }
}

fun GraphBuilder.Node.D1.weightedLayer(id: String = Uuid.random().toString()) = addCompute(
    WeightedD1(
        inputI = inputI,
        optimizer = optimizer.d1(inputI),
        weight = initializer.d1(
            input = listOf(inputI),
            output = listOf(inputI),
            size = inputI,
        ),
        id = id,
    ),
)
```

重みは必ず `IOType.Dx.Global` で保持する。`train` 内で `optimizer.adapt` を呼ぶと `Local` が返るので、`.toGlobal()` でスコープから外して保存する。

`Network.replace(condition, optimizer)`（Optimizer の差し替え・凍結）は、`condition` に一致した各層の `update(optimizer: Optimizer)` を呼ぶ。重みを持つカスタム層は上記のように override し、自層の重み形状で `optimizer.dx(...)` を呼んで作り直したインスタンスに差し替える（Optimizer を保持するフィールドは `var` にしておく）。override しない層は差し替え・凍結の対象にならない。

### GraphEnv

`GraphEnv` — グラフ上の**任意のノードの現在値**を `GraphId` で引ける実行時マップ（`env[id]: Batch<T>`）。現在の層への入力ではない点に注意（層への入力は `expect` / `train` の `input` 引数で渡される）。すべての層に同一の `GraphEnv` インスタンスが渡されるため、他ノードの値に依存した処理（Attention の padding mask が特定ノードの出力を参照する等）で利用できる。

任意のノードを直接参照したい場合（`AttentionBiasD2.mask` 等）は、`Graph.Node.Observe` で対象ノードを観測対象として登録し、その `id` を通じて `env[id]` で読み出す（`AttentionBiasD2Builder.mask(node, value)` の実装を参照）。ネットワークの最初の入力に限らず、`create()` ブロック内で組み立てた任意の中間ノードも参照できる。

## Join（カスタム合流層）

`com.wsr.knist.network.join.Join` の `D1` / `D2` / `D3` を継承する。複数ノードを1つに合流させる層で、組み込みの `add` / `mul` / `max` / `concat`（`docs/llms-usage.txt` の「多入力・多出力モデル」節を参照）と同じ枠組み。

override 必須の抽象プロパティ:

- 出力形状: `outputI`（D1）、`outputI` / `outputJ`（D2）、`outputI` / `outputJ` / `outputK`（D3）

`Compute` と異なり `id` プロパティは無い（`replace` の狙い撃ち対象にならない）。入力側の形状は `expect` / `train` に渡される `inputs: List<Batch<IOType.Dx>>` から都度参照する（各ノードの形状は合流前の `GraphBuilder.Node.Dx` 側で決まるため、層自身は出力形状だけ知っていればよい）。

### Join.D1

```kotlin
@Serializable
internal class MyJoinD1(override val outputI: Int) : Join.D1() {

    // 推論（勾配不要）。inputs は合流する全ノードの値
    override fun IOScope.expect(inputs: List<Batch<IOType.D1>>, env: GraphEnv): Batch<IOType.D1> =
        inputs.reduce { acc, batch -> acc + batch }  // 例: 加算合流

    // 学習（calcDelta に出力を渡すと upstream の delta が返ってくる）
    override fun IOScope.train(
        inputs: List<Batch<IOType.D1>>,
        env: GraphEnv,
        calcDelta: IOScope.(Batch<IOType.D1>) -> Batch<IOType.D1>,
    ): List<Batch<IOType.D1>> {
        val output = inputs.reduce { acc, batch -> acc + batch }
        val delta = calcDelta(output)
        // 戻り値は inputs と同じ順番・同じ数の delta（各入力ノードへの逆伝播分）
        return List(inputs.size) { delta }
    }
}
```

`Join.D2` / `Join.D3` も同じ形（`inputs: List<Batch<IOType.D2>>` 等になるだけ）。

### GraphScope への登録

```kotlin
fun GraphScope.myJoin(vararg nodes: GraphBuilder.Node.D1): GraphBuilder.Node.D1 {
    check(nodes.distinctBy { it.inputI }.size == 1)  // 形状の制約はここでチェックする（例: 全ノード同一サイズ）
    return addJoin(
        join = MyJoinD1(outputI = nodes[0].inputI),
        nodes = nodes,
    )
}
```

`addJoin(join, vararg nodes)` は `object GraphScope` のメンバー関数（`GraphScope` レシーバーの中からはそのまま呼べる。外から呼ぶ場合は `import com.wsr.knist.network.GraphScope.addJoin`）。異なる `Source` に由来するノード同士でも合流できる。合流点（fan-out するノード）の逆伝播 delta は、そこから消費するすべての経路からの寄与の合計になる（これは呼び出し側のグラフ実行が面倒を見るため、`Join` 実装側で意識する必要はない）。

シリアライズ対応（保存・読み込みを使う場合）:
```kotlin
NetworkSerializer.apply { register(MyJoinD1::class) }
```

## Output（カスタム出力層）

`com.wsr.knist.network.output.Output.D1` または `Output.D2` を継承する。

```kotlin
@Serializable
class MyOutputD1 internal constructor(val outputI: Int) : Output.D1() {

    // 推論時の出力（softmax 等の変換のみ。損失計算不要）
    override fun IOScope.expect(input: Batch<IOType.D1>): Batch<IOType.D1> {
        val max = input.max()
        val exp = (input - max).exp()
        val sum = exp.sum()
        return exp / sum
    }

    // 学習時（損失と入力方向 delta を返す）
    override fun IOScope.train(
        input: Batch<IOType.D1>,
        label: (Batch<IOType.D1>) -> Batch<IOType.D1>,
    ): TResult<IOType.D1> {
        val output = expect(input)          // expect を再利用してよい
        val labelBatch = label(output)      // label は現在の output を受け取って目標値を返す
        val loss = /* スカラー損失 */ output.sum()
        val delta = output - labelBatch
        return TResult(loss = loss, delta = delta)
    }
}
```

`TResult<T>` のフィールド：
- `loss: IOType.D0` — バッチ全体のスカラー損失
- `delta: Batch<T>` — 直前の層に渡す勾配

GraphBuilder.Node への登録（`addOutput` は常に `converter` を要求する。組み込み層と同様、Raw系Converterをデフォルトにする版・任意型に変換する版の2つを用意するのが慣例）:

```kotlin
fun GraphBuilder.Node.D1.myOutput() = addOutput(
    output = MyOutputD1(outputI = inputI),
    converter = RawD1(inputI),
)

// converter を使う場合（出力を任意型に変換）
fun <O> GraphBuilder.Node.D1.myOutput(converter: GraphBuilder.Node.D1.() -> Converter.D1<O>) =
    addOutput(output = MyOutputD1(outputI = inputI), converter = converter())
```

シリアライズ対応（保存・読み込みを使う場合）:
```kotlin
NetworkSerializer.apply { register(MyOutputD1::class) }
```

## Optimizer（カスタム最適化器）

`com.wsr.knist.network.optimizer.Optimizer` インターフェースを実装する。`d1` 〜 `d4` で各次元のオプティマイザインスタンスを生成する。

```kotlin
class MyOptimizer(private val rate: Float) : Optimizer {
    override fun d1(i: Int): D1 = MyD1(rate)
    override fun d2(i: Int, j: Int): D2 = MyD2(rate)
    override fun d3(i: Int, j: Int, k: Int): D3 = MyD3(rate)
    override fun d4(i: Int, j: Int, k: Int, l: Int): D4 = MyD4(rate)
}
```

各次元の実装。`Optimizer.D1` 〜 `Optimizer.D4` は抽象クラスで、`adapt(weight, dw)` だけ実装すれば良い。
`maxNorm`（勾配クリッピング）・`stepUnit`（勾配累積。`stepUnit` 回分の勾配を平均して1回だけ重み更新する）はコンストラクタ引数として基底クラスに渡せる。勾配累積・クリッピングは基底クラスの公開 `adapt` が処理するため、実装側で意識する必要はない。

```kotlin
@Serializable
class MyD1(
    private val rate: Float,
    // private var moment: IOType.D1.Global = ... // モーメント等の状態量
) : Optimizer.D1(/* _maxNorm = ..., _stepUnit = ... */) {  // 名前付き引数にする場合、実パラメータ名は _maxNorm / _stepUnit

    // weight: 現在の重み / dw: 勾配 / 戻り値: 更新後の重み（Local で返してよい）
    override fun IOScope.adapt(weight: IOType.D1, dw: IOType.D1): IOType.D1 =
        weight - dw * rate
}
```

`step`（= 実際の重み更新回数。`stepUnit` 回の `adapt` 呼び出しにつき 1 進む）が `protected` プロパティとして参照できる。スケジューラ等に使える。step はオプティマイザインスタンス（= パラメータ）ごとに独立してカウントされる。

## WeightInitializer（カスタム重み初期化）

`com.wsr.knist.network.initializer.WeightInitializer` を実装する。

`Network.create()` に渡した Initializer は `Network` 自身に保持され、`GraphNetworkSerializer` が必ず polymorphic に書き出す。そのため**カスタム Initializer にも `@Serializable` と `NetworkSerializer.register()` が必要**（付けないと `toJson()` / `toCbor()` / `clone()` / `replace()` 系がすべて実行時に失敗する）。なお層ごとの重み初期化は構築時にしか使われないため、保存されるのは `create()` に渡したこの1つだけ。

```kotlin
@Serializable
class MyInitializer : WeightInitializer {
    // input: 前の層の出力形状 / output: この層の出力形状
    override fun d1(input: List<Int>, output: List<Int>, size: Int): IOType.D1.Global {
        val data = FloatArray(size) { /* 初期値の計算 */ 0f }
        return IOType.d1(data)
    }

    override fun d2(input: List<Int>, output: List<Int>, i: Int, j: Int): IOType.D2.Global {
        val data = FloatArray(i * j) { /* 初期値 */ 0f }
        return IOType.d2(shape = listOf(i, j), value = data)
    }

    override fun d3(input: List<Int>, output: List<Int>, i: Int, j: Int, k: Int): IOType.D3.Global { ... }
    override fun d4(input: List<Int>, output: List<Int>, i: Int, j: Int, k: Int, l: Int): IOType.D4.Global { ... }
}
```

`IOType.d1(floatArray)` / `IOType.d2(shape, floatArray)` などで FloatArray から `Global` を生成する（スコープ外で呼ぶと `Global` が返る）。
import: `com.wsr.knist.core.d1`、`com.wsr.knist.core.d2`

シリアライズ対応:
```kotlin
NetworkSerializer.apply { register(MyInitializer::class) }
```

## AttentionBiasD2（カスタムアテンションバイアス）

`attention()` 関数の `biases` ラムダで使われる interface。`forward` だけ実装すれば動作する（`backward` は加算バイアスの場合 delta 素通りがデフォルト）。

```kotlin
@Serializable
data class MyBias(...) : AttentionBiasD2 {
    override fun IOScope.forward(scaled: Batch<IOType.D3>, env: GraphEnv): Batch<IOType.D3> {
        // scaled: (numOfHeads, seqLen, seqLen) のスケール済みアテンションスコア
        // バイアスを加算して返す
        return scaled + myBiasMatrix
    }

    // 加算以外の操作（乗算等）を行う場合のみ override する
    override fun IOScope.backward(delta: Batch<IOType.D3>, env: GraphEnv): Batch<IOType.D3> {
        return delta  // 加算バイアスは素通り（デフォルト実装と同じ）
    }
}
```

import:
```kotlin
import com.wsr.knist.network.process.compute.attention.bias.AttentionBiasD2
import com.wsr.knist.network.GraphEnv
```

### シリアライズ対応

保存・読み込みを使う場合は `@Serializable` を付けて登録する:
```kotlin
NetworkSerializer.apply { register(MyBias::class) }
```

### AttentionBiasD2Builder への追加

`attention(biases = { myBias() })` のように DSL から使いたい場合は、`AttentionBiasD2Builder` を拡張関数で拡張する:
```kotlin
fun AttentionBiasD2Builder.myBias() = copy(biases = biases + MyBias(...))
```

## IOType 演算リファレンス

`Compute.expect` / `Compute.train` / `Output.expect` / `Output.train` / `Optimizer.adapt` はすべて `IOScope` レシーバーを持つため、以下の演算をそのまま呼び出せる。

### 四則演算（elementwise）

| 演算 | D1 例 | 備考 |
|------|-------|------|
| `+` | `a + b` / `a + 1f` | D0 との加算は broadcast |
| `-` | `a - b` / `a - 1f` | — |
| `*` | `a * b` / `a * 2f` | — |
| `/` | `a / b` / `a / 2f` | — |

D1 の `plus(other: IOType.D2, axis: Int)` など broadcast 版も存在する。

### 数学関数（elementwise）

| 関数 | 説明 |
|------|------|
| `exp()` | e^x |
| `ln(e: Float)` | ln(x + e)（数値安定用 e） |
| `pow(n: Int)` | x^n |
| `sqrt(e: Float = 1e-7f)` | √(x + e) |
| `softmax()` / `softmax(axis)` | max 安定化済み。D1〜D4 にあり、D2 以上は `axis` 指定版も持つ |
| `tanh()` | 双曲線正接。`Batch<IOType.Dx>` 版のみ存在（IOType 単体版は無い） |

### 比較・マスク

| 関数 | 説明 |
|------|------|
| `a eq b` / `a eq 1f` | 要素ごと等値（許容誤差あり）。結果は 0f/1f |
| `a gt b` / `a gt 1f` | 要素ごと大なり |
| `a lt b` / `a lt 1f` | 要素ごと小なり |
| `where(condition, onTrue, onFalse)` | 条件マスクによる値選択 |
| `a.where(condition, onTrue, onFalse=this)` | レシーバー版 |

### 集約（reduction）

D1 の例。D2/D3 は `axis: Int` 引数を取るバリアントも存在する。

| 関数 | 戻り値 | 説明 |
|------|--------|------|
| `sum()` | D0 | 全要素の和 |
| `average()` | D0 | 全要素の平均 |
| `max()` | D0 | 最大値 |
| `min()` | D0 | 最小値 |
| `maxIndex()` / `maxIndex(axis)` | D0（D1→D0）/ D1（D2→D1）/ D2（D3→D2） | 最大値のインデックス。D1 は引数なし、D2 以上は `axis` が必須 |
| `topK(k)` | D0 | 上位 k 個からサンプリング |
| `topP(p)` | D0 | 累積確率 p 以内からサンプリング |

### 線形代数

| 関数 | 入力 | 出力 | 備考 |
|------|------|------|------|
| `matMul(other: D1, trans?)` | D2 × D1 | D1 | trans=true で転置 |
| `matMul(other: D2, transA?, transB?)` | D2 × D2 | D2 | — |

### 形状変換・結合

| 関数 | 説明 |
|------|------|
| `broadcastToD2(axis, size)` | D1 → D2 に broadcast（D2 → D3 は `broadcastToD3(axis, size)`） |
| `slice(indices: IntProgression)` | D1 の部分取り出し（D2 版は `slice(indices, axis)`） |
| `interleave(other: D1)` | 2つの D1 を交互に結合（D2 版は `interleave(other, axis)`） |
| `concat(other)` | D1 の結合（D2/D3 は `concat(other, axis)`） |
| `transpose()` | D2 の転置（D3/D4 は `transpose(axisI, axisJ, axisK[, axisL])` で軸入れ替え） |
| `flip(axis)` | D3/D4 の指定軸を反転 |
| `reshapeToD1()` 〜 `reshapeToD4(i, j, k, l)` | コピー無しの形状再解釈。D1〜D4 のどの次元からどの次元へも変換でき、D2〜D4 へは `reshapeToD3(listOf(i, j, k))` のように `List<Int>` 版もある。D1 への変換は引数なし。戻り値は元とバッファを共有するため、保持するときは `toGlobal()` を呼ぶ |

### インデックス操作（埋め込み等で使用）

| 関数 | 入力 | 出力 | 説明 |
|------|------|------|------|
| `gather(other: D2)` | D1(i) × D2(n, j) | D2(i, j) | レシーバーをインデックス列として `other` の行を取り出す（embedding lookup） |
| `scatterAdd(other: D1, n)` | D2(i, j) × D1(i) | D2(n, j) | gather の逆。レシーバーの各行を `other` のインデックス位置へ加算集約（embedding の勾配集約） |

import: `com.wsr.knist.core.index.gather` / `com.wsr.knist.core.index.scatterAdd`（Batch 版は `com.wsr.knist.batch.index.*`）

### 生成

| 関数 | 説明 |
|------|------|
| `IOType.random(i, from, until)` | 一様乱数の D1 を生成（D2〜D4 版もあり） |

### Batch 固有の操作

| 関数 | 入出力 | 説明 |
|------|--------|------|
| `Batch<D2>.unfold(window, stride, dilation, padding)` | Batch<D2> → Batch<D3> | スライディングウィンドウ展開（im2col 相当。conv の実装で使用。D3→D4 版もあり） |
| `Batch<D3>.fold(stride, dilation, padding)` | Batch<D3> → Batch<D2> | unfold の逆操作（重複位置は加算。D4→D3 版もあり） |
| `Batch<D2>.padding(axis, left, right)` | Batch<D2> → Batch<D2> | 指定軸の前後にゼロパディングを追加（axis: 0=i, 1=j） |
| `IOType.D3.toBatch()` | D3 → Batch<D2> | 先頭軸をバッチ次元として再解釈（D2 → Batch<D1> 等もあり） |

四則演算・数学関数・比較・集約には `Batch<IOType.Dx>` レシーバー版も同名で存在する（import は `com.wsr.knist.batch.elementwise.*` / `com.wsr.knist.batch.reduction.*` 等、`core` を `batch` に読み替える）。ここに載っていない演算が必要な場合は io-type モジュールの `core`（IOType 単体用）/ `batch`（Batch 用）パッケージを確認すること。
